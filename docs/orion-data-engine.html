01 Los pilares

Tres técnicas que resuelven cosas distintas

El aprendizaje central del proyecto: streaming y binario no compiten — resuelven problemas ortogonales. Uno cuida la memoria, el otro la velocidad. Juntos, la trifecta.

Formato binario · .odfhecho

El número
como número

Guarda valores como bytes crudos, no como texto XML. Leer ≈ un memcpy; escribir se salta el impuesto XML/zip del xlsx.

Resuelve la velocidad. Leer ~11× · escribir ~8× vs xlsx.
Columnar + SIMDhecho

El procesador
en ráfaga

Cada columna contigua y tipada (Vec<i64>, Vec<f64>). El CPU recorre y agrega en ráfaga; las queries vuelan.

Resuelve el cómputo. sum/filter/group sobre memoria contigua.
Streaminghecho

Memoria
acotada

Transmite el TXT por chunks y escribe archivos liberando cada bloque. La RAM se acota a un chunk, no al tamaño del archivo.

Resuelve la memoria. Procesa archivos más grandes que la RAM.

02 El insight

Por qué “fila por fila” no era el problema

La intuición decía que escribir fila por fila es lento. Medimos, y la causa real es otra — y esa distinción es la que define el diseño.

Streaming → memoria

No satura la RAM

Nunca tiene todas las filas en memoria a la vez. Resuelve el “no colapsar el hardware” con archivos gigantes. No hace nada por la velocidad.

Binario → velocidad

No paga el impuesto xlsx

En Rust, escribir celda por celda es barato (no como openpyxl con objetos Python). El costo del xlsx es el formato: convertir a XML y comprimir en zip. El binario se lo salta.

▲ MEDIDO

Escribir 120 000 filas: binario ~330 ms vs xlsx ~2600 ms = ~8× más rápido. Mismos datos, misma máquina. El impuesto no es el bucle — es ser xlsx.

04 La API construida

Las funciones que ya existen

Módulo frame. Dos herramientas por cada extremo: una para humanos (Office), otra para volumen (binario). Nunca se toca lo que ya funciona.

frame.open(ruta)Abre CSV, TXT o .odf — auto-detecta el formato. El usuario nunca elige binario.
frame.from_txt(txt, sep)Carga un TXT delimitado a un frame columnar tipado.
frame.save_odf(f, ruta) · load_odf(ruta)Persistencia binaria explícita. Carga ~11× más rápida que CSV.
frame.to_excel(f, ruta, split)Frame → xlsx, 1 archivo multi-hoja (parte por el límite de 1M).
frame.txt_to_excel(txt, base, sep, split)Streaming → base_N.xlsx. Para humanos. Memoria acotada.
frame.txt_to_odf(txt, base, sep, chunk)Streaming → base_N.odf binario. Memoria acotada Y ~8× más rápido.
frame.scan_stats(ruta, columna)Stats (min/max/mean/std) en streaming, sin cargar todo.

05 La cara visible

El pipeline TXT → salida, en Orion

El motor (binario, streaming, tipado) es invisible. El usuario elige el destino según el caso.

use "frame" as frame

-- Caso humano: reporte para abrir en Office (más lento, universal)
frame.txt_to_excel("ventas.txt", "reporte", ";", 1000000)
--   → reporte_1.xlsx, reporte_2.xlsx …

-- Caso volumen: rápido y con memoria acotada (~8× vs xlsx)
frame.txt_to_odf("ventas.txt", "datos", ";", 500000)
--   → datos_1.odf, datos_2.odf …

-- Después: abrir y consultar. open() detecta el formato SOLO —
-- el usuario nunca escribe ".odf"; el binario es interno.
f = frame.open("datos_1.odf")      -- misma open() que para CSV
f = frame.where_(f, "monto > 0")
total = frame.sum(f, "monto")

07 Lo que decidimos NO hacer (aún)

mmap zero-copy — aplazado a propósito

Estaba en la arquitectura original. Al analizarlo, la decisión honesta fue posponerlo.

Ventajaestrecha

Beneficio condicional

Solo brilla con archivos > RAM o lectura parcial. Para un full-scan no ahorra: el SO igual trae los datos, solo difiere el costo.

Costoalto

Poco sostenible hoy

Requiere unsafe, structs auto-referenciales (el Frame mantiene vivo el mapa) y alinear el formato a 8 bytes. Fragilidad por una ganancia de nicho.

Alternativaelegida

Streaming lo cubre

El objetivo real (“no saturar la RAM”) ya lo logra el streaming, con código seguro. mmap queda para “algún día, si de verdad manejas archivos > RAM”.

De propuesta a motor real, con las tres técnicas trabajando juntas.

Binario para la velocidad, columnar para el cómputo, streaming para la memoria. La regla que guió todo: cada pieza resuelve un problema distinto, y ninguna se sacrifica por otra.

Lo que sigue es pulir bordes — cargar/concatenar varios .odf, tipos consistentes entre chunks — no reconstruir. La arquitectura ya está de pie, medida y con 357 tests en verde.
